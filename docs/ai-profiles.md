# AI task profiles and previews

Platform operators with an explicit `platform_operator.ai` grant and MFA verified within 15 minutes can prepare and activate shared AI profiles. The grant is provisioned through the schema-owner connection; Business ownership, tax access and reconciliation access do not grant it. Every preview also requires current Owner/Admin membership in the selected Business and explicit authorization to use that Business context. Operators do not bypass Business RLS.

The Business profile links to **AI profiles and previews** for authorized operators. Review and approve Business knowledge first. Prepare an immutable profile draft, run representative extraction and drafting previews against reviewed samples, inspect the complete output and usage, and accept each representative output with a review note. Activation checks both accepted previews for that exact profile and the current approved Business knowledge version. A draft or a model change cannot inherit validation from another version. Rejected outputs require a new preview or revised draft. Changes to approved Business knowledge invalidate old preview evidence for subsequent activation.

No preview sends a message, grants commercial authority, changes recipients, retrieves web pages or executes model-provided instructions. Source/message content and model output are untrusted. Output schemas, exact extraction evidence quotes and drafting answer references are validated. Drafts still require human review for factual quality; schema validation alone cannot establish quality. Approved knowledge, sample text, actor, version, output, validation and attempt history are persisted. UI validation and acceptance remain human-owned.

## Configuration

Only server composition reads credentials. Configure `OPERATOR_OPENAI_API_KEY` and, when system fallback is explicitly approved, `OPERATOR_AI_GATEWAY_API_KEY`. Use service-operator-owned API accounts and project keys. Business customers cannot upload credentials or grant global AI authority. Subscription sign-in tokens are not accepted. Missing keys never enable SDK environment defaults or Vercel OIDC authentication.

`AI_CONFIGURATION_JSON` must match `aiConfigurationSchema` in `src/models/ai.ts`:

- `revision`: an operator-controlled identifier for this approved capability/funding configuration. Change it when approvals change; profiles tied to an old revision stop at setup.
- `models`: explicit `openai/<model-id>` entries, `providers: ["openai"]`, approved `tasks` (`extraction`, `drafting`), `structuredOutput: true`, numeric `maxInputChars` and `maxOutputTokens`, and an `evidence` reference recording the reviewed provider capability. No model, price or commercial allowance is preselected.
- `openaiFunding`: `state` (`confirmed`, `missing`, `exhausted`, `unknown`), `source` (`linked_api_credits` or `purchased_api_credits`), and an operator evidence `reference`.
- `gatewayFunding`: the independently confirmed `state` and evidence `reference`. This is required for profiles approving system fallback.

References contain safe operator descriptions, never API keys or billing payloads. They are confirmations, not a live balance integration. Grant eligibility, remaining credit, model availability, provider terms and current rates require account-specific verification. Configuration does not provision a grant, claim credits, buy funding or activate Exa.

Every profile requires explicit input/output limits, total deadline, combined per-task attempt cap, per-task system-fallback cap, shared profile attempt allowance and shared fallback allowance. Technical ceilings are validation bounds, not approved business defaults. Allowances cover previews and workflows across all Businesses using that profile. Failed and uncertain attempts consume reserved allowance. A replacement version requires explicit limits and new validation; it never silently tops up the current version.

## Routing, recovery and accounting

The Vercel AI SDK calls OpenAI directly with the operator API key for the primary route. This preserves the operator's linked organization/project funding path while avoiding Gateway's automatic BYOK-to-system fallback. Explicitly approved fallback uses AI Gateway with only the `openai` provider, no model fallback list and an empty request-scoped BYOK key set, excluding cached dashboard keys. The SDK uses `maxRetries: 0`, no tools and bounded cancellation/deadlines. OpenAI response storage is disabled. The application owns the combined attempt cap, reserves allowance in PostgreSQL before each generation and stops on uncertain acceptance, invalid output, interruption or exhausted allowance. Timeouts and server errors are treated as uncertain, rather than assumed safe to repeat.

Each task uses one stable request key. Reusing it returns the recorded task without another generation; changing its payload conflicts. Durable job retries must retain that key. Unfinished tasks and uncertain attempts remain visible and cannot replay. An operator may explicitly prepare another preview, review the input again and authorize a new task. SDK/network retries, Effect retries and Trigger recovery do not create another AI attempt under an old key. Trigger.dev remains the durable host; discovery adapts the conventional profile service at its existing Effect boundary.

Each attempt records its ordered number, requested route, observed provider/model and credential source when known, token usage when reported, latency, funding evidence and safe failure category. OpenAI API cost remains unknown without an authoritative reported amount. Gateway generation lookup can provide its actual debit and provenance; absent breakdowns remain unknown, distinct from zero. Generation lookup uses the same cancellation signal and cannot retry inference. Provider and Gateway meters are never added into an invented bill or deducted from subscription allocation. Failed or ambiguous calls may have incurred charges even when usage/cost is unknown.

The selected [OpenAI API credit benefit](https://developers.openai.com/api/docs/guides/chatgpt-api-credits) applies to the linked API organization and differs from ChatGPT/Codex subscription allocation. Account billing evidence is needed to establish that a particular grant funded a request. Vercel documents [automatic BYOK system fallback and its credit charges](https://vercel.com/docs/ai-gateway/authentication-and-byok/byok), [provider restrictions](https://vercel.com/docs/ai-gateway/models-and-providers/provider-options), and [generation lookup with optional cost breakdowns](https://ai-sdk.dev/providers/ai-sdk-providers/ai-gateway). The implementation uses the installed AI SDK 7 and Gateway 4 APIs.

## Shared workflow boundary

`executeWorkflow` resolves the current approved profile under current actor/Business authorization. It accepts extraction or drafting tasks and stable request keys; inquiry handlers can use the same service without adopting Effect. Extraction requires current discovery-management authority; drafting requires sales-work authority. `createProfiledDiscoveryProvider` delegates retrieval unchanged to the selected retrieval adapter and uses this service for evidence review. The discovery host supplies the persisted work identity and operation ID, and rechecks the current run, session, schedule and approved discovery scope before every nested AI attempt. Model changes cannot replace Exa, expand coverage, grant retention/display/export rights, change discovery budgets or send messages. Existing discovery checkpoints and Trigger recovery remain intact.

The production retrieval adapter remains the separate #16 integration. No live Exa capability or unsigned source contract is activated here. Deterministic discovery integration exercises real persistence, profile switching, evidence, budgets, and duplicate-worker handling through the application seam. Live provider/funding verification requires actual operator configuration and remains separate from these deterministic tests.

## Database

Apply the additive schema using `pnpm db-push` after inspecting the configured owner target. The change adds six AI tables and the default-false AI operator grant. The security step restores forced RLS, policy expressions and restricted column grants. Profiles/activation/reviews are immutable except for dedicated usage counters; Business task/attempt records stay scoped. The global activation pointer contains only its ID, version and profile ID; activation evidence, actor, time and notes live in a separate Business-scoped audit. Composite execution/Business foreign keys prevent cross-Business attempt or review references. Runtime verification checks these protections. No migration files, reset, Business operator promotion or credential insertion is required.
