# Use one interactive PostgreSQL access and schema stack

Use Drizzle ORM and Drizzle Kit with node-postgres for the Next.js application and Trigger workers, preserving interactive transaction support on the selected Node runtimes. Runtime traffic uses Neon's pooled endpoint, while schema updates use a direct owner connection; Business context and protected queries belong in the same transaction under a restricted database role. At the user's request, production schema changes now use reviewed, committed SQL from `pnpm db-gen`, applied through `pnpm db-mig` with migration history and serialized execution. Keep the security preparation and verification steps around migration application because generated table DDL does not install every source-owned helper, grant or deferred constraint; retain `db-push` for disposable development databases and the separately reviewed recovery schema workflow.
