## What to build

A salesperson links channels and repeated messages to the right buyer and Opportunity while keeping independent needs separate.

## Acceptance criteria

- [ ] Show a buyer's conversations and multiple Opportunities, with explicit association/correction actions and retained provenance.
- [ ] Keep repeated messages about one need in its Opportunity; two independent needs for the same buyer remain distinct.
- [ ] Avoid speculative cross-person or cross-Business merges; ambiguous association is surfaced for review with an accountable next action.
- [ ] Preserve engagement, ownership and outcome history when an authorized association is corrected.
- [ ] Complete the relevant persistence, application/API and UI path; verify observable state and outbound effects at the primary application seam with real internal persistence, deterministic providers and a controlled clock.
- [ ] Enforce actor/Business scope for the reads, writes, provider events and queued work touched here; validate external data and keep public errors and diagnostics safe.
- [ ] Apply the accepted discovery/handler/worker boundaries and frontend stack/design skills. After final code edits, run Prettier and lint, fix failures and report the results.
