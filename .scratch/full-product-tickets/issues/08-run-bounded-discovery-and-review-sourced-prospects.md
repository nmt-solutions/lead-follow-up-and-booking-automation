## What to build

A Business submits a Discovery brief and receives a persisted, budget-bounded run with evidence-backed potential buyers.

## Acceptance criteria

- [ ] Create a brief from the offering, buyer types, product requirements, geography and exclusions; enforce configured active reach and explicit coverage.
- [ ] Compose discovery in Effect behind conventional Next.js handlers and a Trigger task boundary, with deterministic search/AI ports and real application persistence.
- [ ] Persist sourced match reasons, URLs, check dates, run progress, usage, partial results and stop reasons; enforce an authorized initial run budget across concurrent work.
- [ ] Keep private Business context isolated and untrusted pages subordinate to approved capabilities, recipients and spend; discovery never creates engagement or sends a message.
- [ ] Distinguish expected failures, defects and interruption at host boundaries; interruption preserves completed work and cannot outlive its transaction or authorize extra calls.
- [ ] Complete the relevant persistence, application/API and UI path; verify observable state and outbound effects at the primary application seam with real internal persistence, deterministic providers and a controlled clock.
- [ ] Enforce actor/Business scope for the reads, writes, provider events and queued work touched here; validate external data and keep public errors and diagnostics safe.
- [ ] Apply the accepted discovery/handler/worker boundaries and frontend stack/design skills. After final code edits, run Prettier and lint, fix failures and report the results.
