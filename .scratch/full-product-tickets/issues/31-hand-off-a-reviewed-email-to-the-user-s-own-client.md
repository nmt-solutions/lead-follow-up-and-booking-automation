## What to build

A user opens, copies or downloads an approved draft and sees preparation and later sending evidence accurately distinguished.

## Acceptance criteria

- [ ] Provide a standards-based email-client handoff and copyable recipient/subject/body; validate any downloadable draft format/provider-specific compose path for declared clients.
- [ ] Explain account selection accurately: opening a compose link cannot force the From account, attach files universally or prove Send was pressed.
- [ ] Persist Prepared, User-marked sent, Sent-folder observed and Reply observed as distinct evidence states; a click is not sending and a Sent-folder observation is not delivery.
- [ ] Correlate stronger observations only through authorized functioning mailbox synchronization; narrower forwarded/BCC/manual evidence never masquerades as full sync.
- [ ] Retain recipient, authority and eligibility checks, and require the applicable approval before any automated follow-up.
- [ ] Complete the relevant persistence, application/API and UI path; verify observable state and outbound effects at the primary application seam with real internal persistence, deterministic providers and a controlled clock.
- [ ] Enforce actor/Business scope for the reads, writes, provider events and queued work touched here; validate external data and keep public errors and diagnostics safe.
- [ ] Apply the accepted discovery/handler/worker boundaries and frontend stack/design skills. After final code edits, run Prettier and lint, fix failures and report the results.
