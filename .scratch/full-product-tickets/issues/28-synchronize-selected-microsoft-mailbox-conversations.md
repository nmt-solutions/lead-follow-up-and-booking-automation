## What to build

A Business connects Outlook/Microsoft mail and sees selected inquiries and manual replies reflected in the sales workflow.

## Acceptance criteria

- [ ] Use native Microsoft Graph OAuth/API with secure Business-bound tokens, grant separation and refresh/reconnect/revoke behavior.
- [ ] Honor selected mail/history scope and validated account support; recover incremental/subscription gaps with deduplication and retained sync state.
- [ ] Feed inquiries/manual replies into correct Opportunity association, unanswered-sequence cancellation and cross-channel takeover.
- [ ] Show connection/visibility failures honestly, pause affected follow-ups and retain the applicable application approval/assessment and account-licence prerequisites.
- [ ] Complete the relevant persistence, application/API and UI path; verify observable state and outbound effects at the primary application seam with real internal persistence, deterministic providers and a controlled clock.
- [ ] Enforce actor/Business scope for the reads, writes, provider events and queued work touched here; validate external data and keep public errors and diagnostics safe.
- [ ] Apply the accepted discovery/handler/worker boundaries and frontend stack/design skills. After final code edits, run Prettier and lint, fix failures and report the results.
