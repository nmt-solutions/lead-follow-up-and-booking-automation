## Acceptance criteria

- [ ] Capture the actual pilot Business/offering, goal, baseline, numeric success criteria, scope, approved cash/time/spend limits and upfront pilot/renewal quote without invented commercial defaults.
- [ ] Show capability-specific preflight for current authority/MFA, source/market coverage, budgets, retention/offboarding, tax/billing configuration and chosen sender/mailbox/WhatsApp/calendar paths.
- [ ] Live Exa activation requires completion evidence from existing issue #2; other provider credentials, verification/assessment costs and approvals remain explicit runtime launch gates rather than coding blockers.
- [ ] Require separately validated selected channel/account paths and truthful sender/reply readiness; unsupported or unconfigured capabilities stay unavailable while deterministic workflows remain demonstrable.
- [ ] Record measured quality, sales outcomes, channel health, contribution inputs and an evidence-backed paid renewal; only then record the materially different workflow used to assess configuration reuse.
- [ ] Completing the software/checklist does not claim that a real pilot, provider approval, legal review or paid renewal has already happened.
- [ ] Complete the relevant persistence, application/API and UI path; verify observable state and outbound effects at the primary application seam with real internal persistence, deterministic providers and a controlled clock.
- [ ] Enforce actor/Business scope for the reads, writes, provider events and queued work touched here; validate external data and keep public errors and diagnostics safe.
- [ ] Apply the accepted discovery/handler/worker boundaries and frontend stack/design skills. After final code edits, run Prettier and lint, fix failures and report the results.
