## What to build

An operator deploys the selected stack and demonstrates recovery of a Business's records and durable work in an isolated environment.

## Acceptance criteria

- [ ] Configure isolated environments, server-only secrets and deliberate supported Vercel/Neon/Trigger regions, preserving pooled runtime versus direct migration access and non-bypassed RLS.
- [ ] Apply/recover a reviewed migration and restore representative Business data and queued work in a disposable recovery environment, verifying application-visible records and no duplicate outbound effects.
- [ ] Record configured backup/restore objectives, retention and file-recovery limitations; do not claim an untested recovery guarantee or Virginia placement for R2.
- [ ] Expose actionable health/readiness evidence and reconcile the selected service/retention costs; production setup requires actual credentials and verified environment configuration.
- [ ] Complete the relevant persistence, application/API and UI path; verify observable state and outbound effects at the primary application seam with real internal persistence, deterministic providers and a controlled clock.
- [ ] Enforce actor/Business scope for the reads, writes, provider events and queued work touched here; validate external data and keep public errors and diagnostics safe.
- [ ] Apply the accepted discovery/handler/worker boundaries and frontend stack/design skills. After final code edits, run Prettier and lint, fix failures and report the results.
