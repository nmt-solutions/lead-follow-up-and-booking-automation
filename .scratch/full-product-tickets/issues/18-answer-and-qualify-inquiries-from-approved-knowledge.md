## What to build

Incoming inquiries receive grounded answers and only missing qualification questions, with human escalation for uncertainty.

## Acceptance criteria

- [ ] Use current approved Business knowledge and task profiles for drafting/answering while retaining deterministic test adapters.
- [ ] Accumulate qualification facts across messages, ask only for missing requirements and apply that Business's rules and conversion goal.
- [ ] Route unavailable knowledge, unsupported requests and unsafe model output to an accountable human with context rather than fabricating facts.
- [ ] Respect takeover and current channel/authority gates; inbound content cannot change tools, recipients, commercial authority or budget.
- [ ] Complete the relevant persistence, application/API and UI path; verify observable state and outbound effects at the primary application seam with real internal persistence, deterministic providers and a controlled clock.
- [ ] Enforce actor/Business scope for the reads, writes, provider events and queued work touched here; validate external data and keep public errors and diagnostics safe.
- [ ] Apply the accepted discovery/handler/worker boundaries and frontend stack/design skills. After final code edits, run Prettier and lint, fix failures and report the results.
